### 全局代理

排除系统代理/VPN/PAC 自动发现、HTTPS 代理端点、新代理协议、FTP/WebDAV/更新请求、用户手工运行命令、强制重连及自动搬迁既有通道。基础代理协议仍按现有 C 系列能力处理，不借本项重写连接系统。**用户已确认按上述边界纳入，并要求实施与本地验证；实现结果见下节。**

### MCP

建议纳入 **G01–G15 完整能力，以及 I06/I19/I26/I27/A10 的 MCP 联动部分**。模型由外部客户端负责；默认关闭，本机手动开启。功能范围限既有七个工具：`sessions_list`、`session_state`、`task_start`、`command_submit`、`operation_read`、`task_end`、`task_stop`。普通 SSH Agent、诊断日志和测试快照不算已实现 MCP。

建议以两批交付同一已确认范围：先闭合 G01–G12 的控制/记录基础及对应五项联动，再交付 G13–G15 的检索/回放/导出管理；后批未完成时只能声明前批通过，不能宣称 MCP 15 项完成。这是交付拆分，不是新功能编号，也不是允许先开放不完整保护的自动写入。

**G08 启用门槛：** G01/G02 通道与身份、G03 授权、G04 审批、G05/I26 集成、G07 所有权、G10/I19/I27 最终输入仲裁、G11 敏感输入、G12/I06 持久记录和 A10 有界生命周期都闭合后才能开放自动输入。G09 只读取属于该操作的已持久化输出。G03 与 G12 的相互依赖表示授权即起记录，必须一起设计验证，不是无限先后循环。G13–G15 依赖 G12 封口与完整性，并不能替代 G12。

上述门槛按关联条目中与自动控制有关的子能力验收：例如 I06 的持久记录必须先完成，但其 G13–G15 存档入口可在后批交付；I27 的最终写入门禁必须先完成，只读回放宿主随 G14 交付。部分通过不能将该条目的全部新版增量标为完成。

如果只想先做观察能力，需要另选明确的子范围并重新标注未选行，不能把“先做 MCP”理解为省略门槛后开放 command_submit。本清单推荐完整范围，尚无实现授权。
