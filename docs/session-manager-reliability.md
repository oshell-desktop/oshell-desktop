# 会话管理连续操作核查

归属 SF-S07，关联 SF-S01、SF-S04、SF-S06、SF-Y17。处理用户报告的粘贴后无法编辑、短时间不能再次复制粘贴，以及新目录中新建表单偶发不出现；不新增功能编号或共享字段。

## 已复现并修正的逻辑问题

1. `App.post` 原来仅唤醒主窗口重绘，由视图的 `drain` 执行后台完成回调。主窗口被遮挡或最小化、辅助窗口仍在使用时，配置事务结束不保证忙碌状态立即释放。隐藏 Windows 原生窗口回归在修复前等待 5 秒仍得到 `busy=true`。现在通过 `Window.Update` 调度 UI 事件循环处理队列，同一批回调合并唤醒、按原顺序执行；视图仍可 drain，但完成处理不依赖重绘。
2. 后台同步和激活刷新只避让属性/设置弹窗，没有避让会话管理窗口及行内改名。粘贴后的修改触发同步可能重新占用全局配置锁。现在管理窗口存续时不开始同步提交，已经读到的计划丢弃并标记待重新比较；关闭管理窗口后恢复。关闭管理窗口转入属性编辑时仍由编辑状态阻止同步，不在转换间隙提交旧计划。定时同步保持排队，不丢弃修改。
3. 编辑入口遇到配置忙碌直接返回，窗口仍可能显示先前的“已粘贴”状态。现在显示保存/同步等待提示，新建和行编辑按钮在事务进行时禁用；直接编辑请求也提供明确原因。仍保留真实事务和密码锁保护，没有以提前解锁绕过并发校验。

## 有限验证范围

- 新建空目录后，SSH/SFTP/FTP 的上下文菜单可以构建对应属性表单。
- 粘贴后立即打开属性、保存或取消、回到原目录和选择，再次复制粘贴，连续三轮；检查落库和合成密码身份绑定。
- 同步启动、准备结果、提交、窗口激活刷新和跨窗口避让；一次性同步触发仍留在队列。
- Windows 隐藏窗口中不渲染应用视图，复制事务仍完成并允许立刻编辑；测试窗口自行退出。
- 真实忙碌期间拒绝编辑并提示，解除后立即可编辑；保持原生窗口在绘制期间关闭的防崩溃回归。

日志保存在 `validation/manager-session/`。这些回归证明上述具体问题及修复，不宣称已逐个复现用户环境的所有触发条件，也不替代真实 macOS/Swift 互通或 Linux 桌面验收。本轮未操作用户桌面窗口或真实连接。
